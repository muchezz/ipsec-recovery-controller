# Privileged legacy diagnostics

On gateways where stroke's `/run/charon.ctl` is root:root 0770, the HTTPS agent must not receive root, sudo, a privileged group, or direct socket access. The optional helper runs independently as root and brokers only `/usr/sbin/ipsec statusall`. The controller still chooses SSH or HTTPS; this backend selection is local to the HTTPS agent.

## Deployment

Install the same pinned v0.3.0 wheel in separately provisioned virtual environments on the hosts needing each role. The helper executable is `ipsec-recovery-diagnostics-helper`; it does not start the controller or HTTPS agent. Its virtual environment, dependencies, binary, systemd units, and parent directories must be root-owned and not writable by the agent. Avoid user site packages and PYTHONPATH overrides for the root service. The system `ipsec` executable, wrapper scripts and their configuration must also be trusted and root-owned.

Create a dedicated unprivileged `ipsec-agent` service user/group, without login access or membership in groups granting stroke access. Install the provided helper `.socket` and `.service` units. systemd creates `/run/ipsec-recovery-helper.sock` as root:ipsec-agent 0660 in the existing root-owned `/run` directory. Do not precreate or chown this socket manually. Enable/start `ipsec-recovery-diagnostics-helper.socket`; the service starts on first connection. `Accept=no` is implicit: a single service serializes requests. Backlog is four; excess or delayed clients may time out, never execute recovery.

The helper resolves `--agent-user ipsec-agent` through the local account database at startup and compares every connection's Linux SO_PEERCRED UID to that exact UID. Group membership alone is insufficient. If using another dedicated identity, change both SocketGroup and --agent-user, plus the agent unit User/Group. UID 0 is rejected as an agent identity. Restart the helper after identity changes. Do not reuse the dedicated UID for other services.

Use `config.helper-agent.example.yaml` for the agent and install the optional `packaging/systemd/ipsec-recovery-agent.service.d/helper.conf` drop-in. It orders the agent after the socket, requires it, and masks direct `/run/charon.ctl` access inside the agent's mount namespace. Adapt the mask if the distribution uses another stroke socket location. This drop-in is unnecessary for `inspection_backend: direct`, which remains the backward-compatible default. Do not relax stroke permissions to support the helper backend.

Keep agent certificates and configuration root-owned, readable by the agent group, and not agent-writable (directories 0750, files 0640). The helper does not need TLS keys or the agent configuration. It accepts only its administrative service identity option and the one socket passed by systemd. It refuses ordinary standalone startup without the activated socket or root identity. Keep the helper socket active before starting the helper service manually. The helper has no daemon-specific dependency because strongSwan unit names vary by distribution; absent charon is a diagnostic failure, not a startup or recovery trigger.

Run `systemd-analyze verify` against the installed units on the target distribution, reload systemd, and inspect ownership with `stat`. Verify agent membership and that it cannot open charon.ctl. As the dedicated service account, test an authorized inspection through the HTTPS API. An unrelated account must fail to connect or fail peer authentication. Inspect logs with `journalctl -u ipsec-recovery-diagnostics-helper`. The helper unit clears capabilities, limits address families to AF_UNIX, uses read-only system mounts, and kills its entire cgroup on stop. The agent continues running without root or added capabilities. Do not alter production tunnels to validate diagnostics.

## Protocol and limits

The private Unix protocol accepts exactly the bytes `statusall\n`, followed by write-side EOF. It accepts no JSON requests, names, executable paths, arguments, or shell input. Requests are limited to 32 bytes and a two-second total deadline. Responses are a bounded JSON object containing either UTF-8 output or an error code; raw stderr is never returned. The client verifies that the socket peer UID is root and applies a total response deadline and size limit.

The helper has one active request at a time. It spawns the fixed argv `["/usr/sbin/ipsec", "statusall"]`, with no shell invocation by Python, no stdin, a fixed minimal environment and working directory, and a new process group. The distro's ipsec program may itself be a shell wrapper; it remains trusted system code. The helper bounds stdout to 2,000,000 bytes, stderr to 65,536 bytes, and execution to ten seconds. All exits kill remaining descendants in that process group, reap the immediate child and close pipes. systemd's cgroup cleanup covers service termination. Do not change the helper's executable or limits through network requests. Platforms lacking `/usr/sbin/ipsec` need an administrator-reviewed installation adjustment, not a client-supplied path.

An unresponsive authorized local client can consume the single request slot until its deadline. There is no durable queue, caching, recovery, or automatic fallback to direct inspection. A compromised dedicated agent UID can request repeated status snapshots but cannot change the fixed operation. Root compromise, unsafe system binaries/configuration, escaped subprocess sessions, and kernel compromise are outside this protocol's boundary.

## Parser compatibility and limits

The sanitized fixture reproduces the reported 51-up/11-connecting scale and follows the [upstream 5.8.2 stroke formatter](https://github.com/strongswan/strongswan/blob/5.8.2/src/libcharon/plugins/stroke/stroke_list.c). It is synthetic, not a production capture. Tests cover different IKE/CHILD names, multiple children, selectors, byte/packet counters, plain and UDP ESP SPIs, connecting SAs and malformed/incomplete variants. Long names require no leading whitespace. Parent IDs follow the formatter's IKE-then-children grouping, not name equality.

Stroke is a privileged control interface, not a read-only permission boundary. Only the helper's fixed operation makes this path read-only. Status text is not a transactional snapshot: concurrent rekeying, omitted busy SAs or truncation may produce inconsistent counts. Those fail inspection. Missing selector evidence, orphaned relationships, duplicate IDs, mismatched delimiters and incomplete records must not become missing-tunnel decisions. A syntactically complete snapshot cannot prove that no records were omitted by the daemon, and installed SAs do not prove packet delivery. No live strongSwan daemon was contacted by automated tests; validate the packaged helper and distro-specific permissions on a staging gateway before production deployment.
