# Recovery deployment (v0.4.0)

This is a preparation runbook, not authorization to deploy or enable recovery. Keep existing services and routing in observe/dry-run until a separate reviewed rollout. No production recovery is needed to validate this change.

1. Validate the real gateway's packaged strongSwan 5.8.2 behavior, exact loaded names/selectors, binary locations (`/usr/sbin/ipsec`, `/usr/sbin/ip`), exclusive HA address ownership and fencing in a nonproduction environment. Use one controller authority; multiple independent controller state directories do not provide a global lock.
2. Install the helper environment and dependencies root-owned. Its policy, parent directories, strongSwan config, binaries and updown scripts must be protected from the agent/controller user. Use `config.recovery-helper.example.yaml`; keep `enabled: false`. The helper refuses non-root-owned or group/world-writable policy files. Avoid symlinks in all deployment/state paths.
3. Provision persistent local directories `/var/lib/ipsec-recovery-controller` (controller-owned, mode 0700) and `/var/lib/ipsec-recovery-helper` (root-owned, mode 0700). Back up their SQLite state with SQLite-aware tooling. Do not use `/run`, temporary storage or NFS for recovery state. Preserve state across upgrades/restarts. Before first use, explicitly run `ipsec-recovery-state --directory /var/lib/ipsec-recovery-controller` as the controller identity and the equivalent command for `/var/lib/ipsec-recovery-helper` as root. This offline command only creates state; it never enables a service or initiates a tunnel. It refuses existing files. Missing, empty, corrupt or uninitialized databases block recovery; restore verified backups rather than reinitialize after data loss.
4. Prepare a helper service drop-in that appends `--recovery-config /etc/ipsec-recovery-helper/recovery.yaml` to its existing ExecStart (reset ExecStart before replacing it). Add `StateDirectory=ipsec-recovery-helper` and `ReadWritePaths=/var/lib/ipsec-recovery-helper`. The read-only default unit needs no change. For address inspection, extend `RestrictAddressFamilies` to `AF_UNIX AF_NETLINK`; no network-admin capability is needed for reading addresses or sending stroke requests. The controller service likewise needs `StateDirectory=ipsec-recovery-controller` and a writable state directory under its existing sandbox.
5. Configure mTLS as in the existing agent deployment. Set `inspection_backend: helper`; keep `recovery_enabled: false`. For a separately approved rollout, enable the global agent switch and the explicit connection switch, with matching names/selectors at all three layers. The helper's single-threaded socket broker bounds child concurrency. Increase the controller agent request timeout to 60 seconds and helper client timeout to 60 seconds for the several bounded commands in a recovery request. Timeouts never trigger retries.
6. Prepare `mode: recover` and a strong `IPSEC_CONTROLLER_WEBHOOK_TOKEN` only for an approved rollout. Restrict webhook ingress to Alertmanager; retain PagerDuty/Mattermost routes, receivers and escalation policies. Map `PakakobeIPsecTunnelMissing` using existing trusted configuration, retaining the alert's 30-minute rule. Do not add generic label-to-command mapping.
7. In staging, run the focused recovery tests and test missing, installed, negotiation, duplicate, standby, role transition, command timeout, verification failure, repeated/concurrent delivery and restart persistence. Confirm structured `audit_event` records reach the existing persistent journal/log collector on controller, agent and helper. Keep recovery disabled if any evidence is incomplete.

Disable future actions by changing the controller back to `dry-run` and disabling agent/helper switches during a separately authorized change. An already admitted stroke operation may continue; disabling does not tear down SAs. For uncertain outcomes, inspect live state manually and preserve incident records. Breakers expire automatically after a quiet period. Do not clear cooldown/deduplication data as an automatic response.
