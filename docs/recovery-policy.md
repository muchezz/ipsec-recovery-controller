# Recovery policy (v0.4.0)

Recovery is disabled by default. `observe` and `dry-run` retain their read-only behavior. Only `mode: recover`, an authenticated webhook, a connection's `recovery_enabled`, the agent's global and connection switches, and an enabled root helper policy permit initiation. SSH and direct agent execution remain read-only. PagerDuty/Mattermost and Alertmanager routing are unchanged.

Only an unambiguously mapped, firing `PakakobeIPsecTunnelMissing` alert is actionable. It needs a fingerprint and a timezone-aware `startsAt` between 30 minutes and 24 hours old. Resolved, unmapped, overlapping, malformed and truncated alerts cannot execute. The 24-hour bound deliberately requires manual handling for old incidents. Labels select configured rules; they never supply command names, selectors or addresses.

Admission uses persistent SQLite state and kernel file locks on a local filesystem. All controller workers must share one state directory. There is one global operation and an additional connection lock. Incident identity uses the configured connection and normalized start time, independently of fingerprint changes. Deduplication has no automatic expiry. A 3600-second connection cooldown starts before execution. More than ten arrivals in five minutes opens a persistent 30-minute breaker, extended by continued storms. Repeated arrivals count toward the storm threshold. These defaults apply independently on the controller and helper. Every admission consumes the incident before side effects, including inspection failures, crashes and uncertain responses. Requests expire after 60 seconds and the helper checks expiry directly before initiation. A persistent global hold blocks new operations for 180 seconds after uncertain outcomes or crashes; a verified success clears it. This covers queued requests and bounded helper work after a transport timeout. There are no automatic retries or destructive rollbacks. State is initialized explicitly with `ipsec-recovery-state`; opening recovery state never creates or repairs the database. Missing/corrupt storage fails closed; never delete it to clear an incident casually.

The helper independently checks root-owned mappings, active HA address ownership, loaded configuration, and live SAs. Controller, agent and helper agree on a mapping digest. Only `/usr/sbin/ipsec up <root-configured-name>` can change state. There is no restart, stop, down, reload or general command interface. Subprocesses have bounded time/output and a fixed environment. Peer credentials restrict socket callers to the configured agent UID; the agent requires mTLS identity.

## Verified strongSwan 5.8.2 subset

The [5.8.2 wrapper](https://github.com/strongswan/strongswan/blob/5.8.2/src/ipsec/_ipsec.in) forwards a single name for `up`. [Stroke initiation](https://github.com/strongswan/strongswan/blob/5.8.2/src/libcharon/plugins/stroke/stroke_control.c) selects a matching child, but can initiate every child under a peer if none matches. Therefore recovery requires identical IKE/CHILD names, a unique peer and child configuration, one canonical CIDR per side, and exact loaded selector evidence. [Status formatting](https://github.com/strongswan/strongswan/blob/5.8.2/src/libcharon/plugins/stroke/stroke_list.c) provides that evidence. The live daemon must identify as exactly 5.8.2.

The helper requires exactly one established IKE_SA and zero children under it. Matching names or selector pairs under any other IKE also block recovery. Installed, duplicate, negotiating, deleting, routed, shunted, pending tasks, missing configuration, unsupported versions and incomplete output block execution. Ownership is rechecked after inspection, directly before initiation. Verification requires exactly one installed CHILD_SA with the expected selectors under the original IKE ID and continued ownership. A command exit code alone never proves success. Verification failure returns an uncertain failure and retains deduplication/cooldown. `recovery_executed: null` means execution may have occurred; never treat that response as permission to retry.

## Limits

Distinct IKE/CHILD names, multiple selector pairs, selector narrowing and other strongSwan versions require manual recovery. No production binaries or gateways were exercised for this implementation. Local HA address ownership must be an exclusive, authoritative active-role signal; deployments without fencing must keep recovery disabled. State checks and stroke initiation are separate daemon operations: an external administrator or autonomous negotiation can race them. The helper serializes its own operations; it cannot make strongSwan's legacy interface atomic. Recovery confirms SA installation, not traffic flow.
